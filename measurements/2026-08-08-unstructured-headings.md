## 大田市「開催要項」— 直せそう

本文は `<h2>開催要項</h2>` の下に、書き手が手で振った全角数字の番号付き
平文段落が続く。

```
開催要項
１．イベント名　しまねふるさとフェア２０２７
２．主催　広島地区観光・物産情報発信事業実行委員会
３．開催日時　2027年1月23日（土）10時～17時、1月24日（日）10時～16時30分
```

**「３．開催日時」の「開催日時」はすでに登録済みの見出し語**（`HELD_HEADS`）。
問題は「３．」という全角数字の番号が、いまの`_marked_sections`が認める
記号（`〇◯○●◆◇■□▲△▼▽★☆`）に入っていないだけ。

### 試した修正と結果

`_MARK_RE` に全角数字+「．」（`[０-９]+[．.]`）を候補として足し、
`extract_dates()` を実際に走らせて確認した（**コミットはしていない**）。

```
修正前: date_start = None
修正後: date_start = 2027-01-23（見出し「開催日」）
```

**公開162件のキャッシュ済み実ページ全件で新旧を突き合わせたところ、
変わったのはこの1件だけ。** 他への誤爆は0件。試しに既存テストスイート
（全17ファイル）もこの修正を仮当てして流したが、全件パスした。

### 危険因子は測った範囲では見つからなかった

「全角数字＋．」の直後に**既知の見出し語が来る**箇所を162件で数えたところ、
1件（この大田市のページ）だけだった。番号付き箇条書きに「１．」の直後が
既知語ではない例（「１．イベント名」など）はもちろん多数あるが、
`_match_head`は完全一致でしか見出しと認めないので、それらは元から
一致しない。

**ただし実例は1件のまま。** 「大田市の1ページで確かめた・162件で誤爆0件」
までは測ったが、この番号付き平文の書き方自体が大田市公式サイトの他の記事に
どれだけ広がっているかまでは数えていない（`_MARK_RE`を直せば効果があるのは
「番号の直後に既知語が来る」記事だけなので、広がっていても実害は無いはず
だが、確かめてはいない）。

## 浜田市「今年度の開催日程」— 直しにくい

本文は `<address>` タグに包まれているが、**`<address>`を見出しタグに
加える必要は無い。** `_marked_sections`は文書全体のプレーンテキストを
スキャンするので、タグの種類とは無関係に○マークを拾える。

```
○今年度の開催日程　2027年 1 月23日 ( 土 ) 10 時～ 17 時 24 日 ( 日 ) …
```

**本当の理由は、「今年度の開催日程」という言い回しが見出し語として
登録されていないこと。** `_match_head`はマークの直後から1文字ずつ積み上げて
完全一致を見るため、「今」「今年」「今年度」…と積み上げても`_ALL_HEADS`の
どれとも一致せず、「開催日程」の4文字にすら届かない。

### なぜ大田市と違って直しにくいか

大田市の番号マークは**「記号の種類が足りなかった」**だけで、直後の語
「開催日時」はすでに登録済みだった。浜田市は**語彙そのものが無い**。

`今年度の開催日程`を丸ごと新語として足すのは実例1件のための専用対応で、
再利用性が無い。かといって「開催日程」を単体で`HELD_HEADS`に足すと、
`_match_head`は完全一致なので「今年度の開催日程」にはやはり届かない
（見出し全体が「今年度の」から始まっているため）。**部分一致・接尾一致を
許すよう`_match_head`の側を変える**という選択肢もあるが、これは
`_marked_sections`全体の挙動を変える大きな変更で、実例1件のために
踏み込む理由が無い。

**162件中、この形の言い回しは1件だけ**（別途測定。「開催/日程/日時/期間/日」
を含む未一致ラベルを洗い出して確認）。他の11件はいずれも無関係な内容
（賞品名・会場・注意事項など）か、別の抽出経路（`period_box`の構造化宣言
など）で既に正しく日付が取れているページだった。
