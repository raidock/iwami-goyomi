# 石見暦（いわみごよみ）

浜田・江津をはじめとする**石見地域の催しを自動で集めて、ひとつの暦にまとめて公開する**ツールです。

暦は、これからの予定表であると同時に、過ぎたことの記録でもあります。
終わった催しを消さずに残しているのは、そのためです。
市町のお知らせは9割が入札・人事・計画といった行政内部の情報で、住民向けの催しはそこに埋もれています。
このツールは、その中から**催しだけを掘り出して並べます**。

もともと「山陰の蚤の市を集める」ツールとして作り、対象を地域イベント全般に広げました。
蚤の市版は `main_nomi.py` に残してあります。

## 3つの種別 — 時間軸が違うものを分けて扱う

同じ「地域の情報」でも、住民にとっての時間の意味が違います。ここを分けないと
一覧が使いものになりません。

| 種別 | 時間軸 | 並び順 | 表示 | 住民の動詞 |
|---|---|---|---|---|
| **催し** | 開催日 | 日付の昇順 | 8月9日(日) | 行く |
| **募集** | **締切** | **締切の昇順** | **締切まであと3日** | 申し込む |
| **制度** | なし | カテゴリ順 | 随時 | 使う |

- **募集だけ並び順が逆**です。締切が近いものほど上に来ないと役に立ちません
- **締切が14日以内のものがあるときだけ**、募集ブロックが催しより上に繰り上がります
- 催しにも申込締切があるので、開催日とは別に「申込締切 8/1・あと5日」を添えます

### 判定順序に意味があります

「出前講座を**ご利用ください**」は講座という催しの語を含みますが制度です。
そのため制度を最初に判定します。

1. 制度パターン（ご利用ください・派遣・貸出）→ **制度**
2. 催しの名詞（祭り・教室・展・コンサート）→ **催し**
3. 募集の語（募集・応募・締切・コンテスト）→ **募集**
4. それ以外 → 催し

「さざんか祭り アトラクション参加者**募集**」が**催し**になるのは意図どおりです。
本体は祭りで、募集はその一部だからです。

## 詳細ページからの日付抽出

RSSにはタイトルとリンクしかないので、開催日と申込締切は詳細ページを見に行って取ります。
実際のページを読んで設計したので、次の2つに対応しています。

**1ページに日付が7個あることがある**

江津市 Go-Con2026 のページには、掲載日／提出期限／公募期間／結果通知／勉強会×3／
最終審査会 の日付が並んでいます。本文を正規表現でなめると、最初に見つかる「掲載日」を
拾って完全に間違えます。

**市によって書き方がまるで違う**

| | 江津市 | 浜田市 |
|---|---|---|
| 構造 | 「提出期限」など見出しで区切られている | 見出しなしの流し込み |
| 有効な手法 | 見出しベース | 文脈語ベース（「までに」「午後1時～」） |

そこで2層構えにしています。

1. **見出しベース** — 「提出期限」「公募期間」「日時」などの見出しを見つけ、
   その直下の日付だけを取る（期間の見出しは終わりの日付が締切）
2. **文脈語ベース** — 見出しがない場合、日付の直後の語で判断する。
   「7月31日（金）までに」→締切、「12月13日（日）午後1時～」→開催日

**どこから取ったかを必ず記録します。** 承認画面に「見出し「提出期限」から取得」と
表示されるので、人が誤りに気づけます。根拠の見えない日付は、公開物では載せないほうが
ましだという考えです。

詳細ページを見に行くのは**仕分けを通過したものだけ**です（177件ではなく20件程度）。
取得間隔は `config.yaml` の `fetch_delay_sec` で調整できます。

## 同一性の判定（uid）について

イベントの同一性は **URL** で判定します。タイトルや開催日は使いません。

v1.5で、uid に開催日を含めていたために事故を起こしました。日付抽出で開催日が
後から埋まった瞬間に uid が変わり、同じイベントが2枚並びました。同時に、締切だけ
取れたものは「既知」と判定され、抽出結果が捨てられていました。

**後から埋まる情報を、同一性の判定材料にしてはいけません。**
`tests/test_dedup.py` がこの事故の回帰テストです。

また収集時は、既知のものを飛ばすのではなく、**新しく分かった情報だけを追記**します
（人の承認・却下の判断は絶対に上書きしません）。

## 情報源は2種類ある

| 種類 | 例 | 性質 | 扱い |
|---|---|---|---|
| 市町の公式サイト | 浜田市 / 江津市 | ノイズ8〜9割。**申込・締切もの**が取れる | 厳しく仕分ける |
| 観光協会 | はまナビ / 江津市観光協会 | イベント専用RSS。**祭り・文化系**が取れる | `trust: high` で緩める |

観光協会のイベントカテゴリRSSには、そもそもイベントしか流れてきません。
自治体サイトと同じ厳しさで仕分けると、語彙にない催しを取りこぼすため、
`trust: high` を指定した情報源はしきい値を下げています。

## 日付の書き方は3通りある

実際のページを読んで分かった、市ごとの違いです。

| 情報源 | 書き方 | 対応 |
|---|---|---|
| 江津市 | 「提出期限」など**見出し**で区切る | 見出しベース |
| 浜田市 | 「7月31日（金）**までに**」と流し込み | 文脈語ベース |
| はまナビ | **【日時】**令和7年11月8日（土） | 【】ラベル＋**和暦** |

観光協会は**和暦**（令和7年＝2025年）で書きます。西暦しか読めないと、
観光協会の日付が1件も取れません。`wareki_to_seireki()` で吸収しています。

## 終わったものの扱い

開催日・締切が過ぎたものは「これからの催し」から自動で外れ、ページ下部の
**畳んだ節「終わった催し・締切」に移ります。消しません。**

「今年はやらない」「最後の開催」も含めて記録として残す方針のためです。
過疎地では、祭りが縮小・統合・消滅していく事実そのものが、
他のどこにも残らない情報になります。

判定には気をつける点があります。

- **日付が分からないものは終了扱いにしない** — 勝手に消してはいけない
- **期間があるものは終わりの日で見る** — 「石見神楽定期公演（2026.4〜2027.3）」は
  開始日が過去でも開催中

## 日付表記のゆれ

地域の情報源は表記が揃っていません。実際に踏んだものを挙げます。

| 表記 | 例 | 出どころ |
|---|---|---|
| 西暦 | 2026年8月3日 | 市の公式サイト |
| 和暦 | 令和7年11月8日 | はまナビ |
| **略記** | **R8.7.20** | 江津市観光協会 |
| 見出し直下 | 「提出期限」→ 8月3日 | 江津市 |
| 流し込み | 7月31日（金）までに | 浜田市 |
| 【】ラベル | 【日時】令和7年11月8日 | はまナビ |
| **タイトル冒頭** | 8月22日（土）有福温泉… | はまナビ |

すべて対応済みです。`tests/test_wareki.py` と `tests/test_extract.py` が回帰テストです。

## カテゴリはタイトルを優先します

説明文まで見ると引っ張られます。実際に「ぶどうまつり」が **神楽・伝統芸能** に
分類されました。紹介文に「石見神楽の上演もあります」とあったためです。
祭りの紹介文はたいてい石見神楽に触れるので、この誤りは多発します。

タイトルで判定し、タイトルに手がかりがないときだけ説明文を見ます。

## 特徴

- **自治体RSSから自動収集**（RSSのURLはサイトから自動発見するので、市町を足すのが楽）
- **ルールベースの仕分け器** — 実データで再現率100%・自動公開ラインの適合率100%
- **承認キュー**（人が最後に見る） — 公開物の品質を守るため、あえて全自動にしていない
- **中止・終了を消さずに残す** — 「今年はやらない」も記録として残す設計
- **種別ごとに時間軸を分けて扱う**（催し／募集／制度）
- **年の推定は掲載日が基準** — 1月の記事の「3/8開催」は今が7月でも2026年3月
- 出力は 公開サイト(HTML) / events.json / events.ics

## 公開する

**[PUBLISHING.md](PUBLISHING.md) に手順をまとめています。**

公開前に `config.yaml` の `site.contact` を必ず埋めてください。空だとサイト上に
警告が出ます。「掲載をやめてほしい」という連絡を受ける窓口がないまま
自動収集サイトを公開してはいけません。

## 使い方

```bash
pip install -r requirements.txt

python main.py collect   # 集める → 仕分ける → 承認キューへ
python main.py review    # 1件ずつ承認する（1日5分）
python main.py build     # 承認済みだけで公開サイトを作る
python main.py status    # いまの状況
```

ネット接続なしで動きを見たいとき:

```bash
python demo_phase0.py    # 浜田市RSSの実データでパイプライン全体を通す
```

## 仕分け器の実測値

浜田市RSSの実データ67件（イベント15 / ノイズ52）を手でラベル付けして計測:

| 指標 | 値 |
|---|---|
| 再現率（拾えた割合） | **100%**（取りこぼし0件） |
| 適合率 | **100%**（誤検出0件） |
| 自動公開ラインの適合率 | **100%**（ノイズ混入0件） |
| 人が見る件数 | 5件 |

取りこぼしゼロを最優先にしています。公開物では「載っていない」ほうが「間違って載っている」より痛いため、
迷ったものは捨てずに承認キューへ送ります。

```bash
python tests/test_classify.py   # この数字を再計測できます
```

### 仕分けで効いているルール

実データから見つけた、間違えやすいパターン:

- **「募集」だけでは判定できない** — 入居者募集・委託事業者募集・指定管理者公募はすべてノイズ
- **「〜の様子を掲載しました」は過去の報告** — イベント語を含むので最も誤検出しやすい
- **「石見神楽」のような魅力的な語もノイズに混ざる**（例:保存拠点基本構想(案)）
- **RSSに数年前の記事が残っている** — 日付フィルタ必須（浜田市RSSに2022年のコロナ情報が残存）
- **催し名が英語のことがある** — DANCE CONTEST を一度取りこぼして修正
- **助詞が挟まると文字列一致が漏れる** — 「意見**を**募集します」「出場者**大**募集」。
  日本語は語の間に助詞や修飾が入るので、揺れやすいものは正規表現で持つ
- **実運用のノイズ率は81%** — 浜田市77件のうち62件が行政内部の情報だった
  （抜粋データでの48%より実態は厳しい）
- **RSSリンクは<head>にあるとは限らない** — 江津市は本文の<a>に3本並べていた。
  自動発見は本文も走査し、「新着」と書かれたものを優先する

## 構成

```
main.py                    collect / review / build / status
collector/
  classify.py              仕分け器（このプロジェクトの心臓）
  review.py                承認キュー
  publish.py               公開サイトのレンダラー
  models.py                Event モデル + 日本語日付パーサ
  sources/
    municipal_rss.py       自治体RSS汎用アダプター（フィード自動発見）
    good_antiques.py       蚤の市アダプター（旧版から継続）
```

## 市町を追加する

```yaml
municipalities:
  - key: masuda_city
    municipality: 益田市
    site: https://www.city.masuda.lg.jp
    # feed_url を省略すると自動発見します
```

## 情報源の構造（石見の場合）

調べた結果、どの市町もこの2層構造でした。

| 層 | 性質 | 例 |
|---|---|---|
| 市町の公式サイト | 行政系。ノイズ多いが**申込・締切もの**が取れる | 浜田市 / 江津市 |
| 観光協会サイト | キュレーション済み。**祭り・文化系**が取れる | はまナビ / 江津市観光協会 |

Phase 1 では観光協会を足す想定です（ノイズが少ないので分類負荷も下がります）。

## 運用の注意

- **一次情報リンクと掲載日を全件に表示しています。** 日程・会場は必ずリンク先で最終確認を
- 収集は1日1回程度に。User-Agent は正直に名乗る設定です
- 保存するのはタイトル・日付・リンクのみで、本文は転載しません
- 掲載を望まれない主催者からの連絡窓口を必ず用意してください
