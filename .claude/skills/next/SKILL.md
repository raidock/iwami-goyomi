# NEXT.md の実行手順

**方針・設計判断・過去の事故は `CLAUDE.md` にあります。ここには手順だけを書きます。**
判断に迷ったら CLAUDE.md を読んでください。
**この文書に方針を写さないこと**（設計判断15。写した瞬間、片方が腐ります）。

---

## 0. 着手前

1. `CLAUDE.md` → `ISSUES.md` → `NEXT.md` の順で読む。
2. コミット規約どおり作業前に `git pull` する。
   **ただし `data/` に手元の未コミット変更があるときは pull しない。**
   ボットの収集コミットと必ず衝突する。状況を報告して指示を待つ。
3. 実行する項目番号と目的を1行ずつ復唱してから着手する。
4. **指示が文中で途切れている、または意図が一意に定まらないときは、
   推測して着手しない。聞き返す。**
   とくに `git pull` / `git push` / `python main.py collect` を勝手に始めない。

---

## 1. 各項目の進め方

**1件ずつ。並行させない。**

### 測る（分類・抽出・収集・語彙を変えるとき）

- **実装より先に実データで測る。** 結果は `measurements/` に置く。
- **予測値をコード・コメント・文書に書かない。** 未実行なら「未計測」と書く。
- 収集の挙動を変えたときは本番の `data/` ではなく複製で測る。

  ```
  cp -R data /tmp/data-trial
  python main.py collect --data-dir /tmp/data-trial
  ```

- **同じ収集を2回走らせない**（相手のサーバを2回叩くことになる）。
- `--pages` で窓を広げたら、`data/manual.json` と重複していないか目視で確認する。

### 実装してよいか判断する（測ったあと・**ここが一番大事**）

**測っただけで実装に進まない。** 既定の条件は次の4つ。

1. 公開中への誤爆が0件
2. 失われる値が0件
3. 再現率・適合率が落ちない
4. 反例がテストで固定されている

**4つとも満たすなら実装する。1つでも欠けたら、実装せずに止まって報告する。**
「惜しいので進める」をしない。止まった報告のほうが価値がある
（実際に、条件3で「締切が開催日に化ける」事故を実装前に止めている）。

**NEXT.md に件ごとの条件が書かれていれば、そちらを優先する。**
何を「誤爆」と数えるかは件ごとに違う。上の4つは、書かれていないときの既定であって、
件ごとの条件を置き換えるものではない。

### 直す

- その項目の範囲だけ。
- 気づいた別の問題は `ISSUES.md` に足すだけにして、勝手に直さない。

### テストを走らせる

```
for f in tests/test_*.py; do case "$f" in *check_links*) continue;; esac; .venv/bin/python "$f" || echo "FAIL: $f"; done
```

- `tests/test_check_links.py` はネットワークを触るので一括実行に入れない
  （設計判断12。必要なときだけ単体で回す）。
- **赤のまま次に進まない。**
- テストは実データ由来。通すために合成データへ書き換えない。

### 画面を見る

- 公開物に関わる変更は必ず。

  ```
  python main.py build
  open out/index.html
  ```

- **テストが緑でも実物を見る。**
  このプロジェクトの事故は21件すべてテストが緑のまま起きている。

### コミット

- 1コミット = 1論理変更。規約は CLAUDE.md。
- **`data/` の変更を機能コミットに混ぜない。**
  承認作業の結果は別コミットにする。
- ドキュメント編集（CLAUDE.md / ISSUES.md）もコードと分ける。

## 2. 報告

- **長い日本語をターミナルに直接出さない**（手元の端末で化ける）。
  `REPORT.md` に書き、チャットにはパスと3行以内の要約だけ返す。
- 測った数字は `measurements/`、残っている課題は `ISSUES.md`、
  方針と事故は `CLAUDE.md`。**同じ数字を2箇所に書かない。**
- `HANDOFF.md` は作らない。
- 完了した項目は `NEXT.md` に印を付け、`ISSUES.md` の片付いた項目は消す。

---

## 3. 禁止

- 実行していないコマンドの結果を書く
- 書いていないファイルを「書いた」と報告する
- 計測前に効果の数値を断定する
- **承認（`python main.py review`）を代行する** — 設計判断3。ここは人の仕事
